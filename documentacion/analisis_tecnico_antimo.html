💰 Motor de Costeo

Cada producto en ventas se busca en Maestro por nombre POS y se clasifica en 5 tipos de costeo:

1. Receta

costo_producto = Σ(ingrediente_i × cantidad_i × precio_unitario_i) Ejemplo: CUARTO DE LIBRA Medallón 115g × $65.96/g = $7,585.40 Pan Hamburguesa × $0.85/g = $178.50 Queso Cheddar × $0.46/g = $23.00 Tomate × $0.04/g = $15.00 Cebolla × $0.02/g = $8.75 Mayonesa × $0.18/g = $36.00 ──────────────────────────── TOTAL COSTO = $7,846.65
Conversión de Unidades
Si receta en gramos pero insumo en unidades, usa tabla UNIDAD_G:
• Pan Baguette: 200g/unidad
• Pan Hamburguesa: 210g/unidad
• Cerveza Corona: 330ml/lata
• Limas/Limones: 12g/unidad

2. Promo 2x1

costo_promo_2x1 = costo_receta_base × factor (generalmente 2) Ejemplo: 2 X 1 APEROL Receta base: 1 Aperol + Agua Tónica = $4,200 Factor: 2 (dos tragos) Costo final: $4,200 × 2 = $8,400 ⚠️ TRAMPA: Si escribís la receta YA duplicada + factor=2 → se multiplica dos veces

3. Pour (Servicio de Botella)

costo_pour = (rendimiento_ml / contenido_botella) × precio_botella Ejemplo: BOMBAY + TONICA (servicio botella) Rendimiento: 60ml (un trago) Botella Bombay: 750ml, $36,615 Tónica 1.5L: $3,000 Costo gin: (60/750) × $36,615 = $2,929.20 Costo tónica: (1500/1500) × $3,000 = $3,000.00 TOTAL: $5,929.20 (precio $13,000 = 54% margen, realista para servicio) ⚠️ Margen >85% en bebida con precio 5+ cifras = probablemente receta de trago con precio de botella

4. Botella

costo_botella = precio_insumo × 1 Ejemplo: AGUA MINERAL 1.5L Precio: $1,500 / botella Costo: $1,500 (margen = precio_lista / costo - 1)

5. Directo

costo_directo = precio_insumo × cantidad_vendida Ejemplo: RABAS (si fuera costeable) Costo por porción: $X Cantidad: 1 porción Costo: $X
Ingredientes Genéricos (Trampa Resuelta)
La hoja Excel tiene "Gin (Brighton/Beefeater)" que resuelve a UN insumo (el más barato).
Solución: Si producto dice marca explícita (BOMBAY, BEEFEATER), crear receta propia en recetas_extra.json con insumo exacto.

Casos Sin Datos (N/D)

  • sin_datos: Tipo de venta = "sin_datos" en maestro
  • Ingrediente sin mapeo: No existe en ALIAS ni COSTO
  • Cantidad no parseada: parse_qty() retorna None
  • Receta no hallada: Nombre normalizado no en RECETAS
  • Combo circular: Combo se referencia a sí mismo → N/D (no cuelga)
✓ Validación de Costeo
• Toda cantidad parseada correctamente (g, ml, unidades, latas)
• Alias resuelven ingredientes genéricos → insumos específicos
• Conversión unidades sin asumir pesos (FALTANTES = error explícito)
• CXU = None → N/D, no TypeError

📈 Cálculo de Márgenes

Fórmula Base

margen_% = (precio_venta_promedio - costo) / precio_venta_promedio × 100 Simplificado: margen_% = (1 - costo/precio) × 100 Ejemplo: Costo: $4,000 Precio promedio: $10,000 Margen: (1 - 4000/10000) × 100 = 60% Caso N/D: Si costo = null o precio = 0 → margen = null (no se fuerza a matriz)

Precio de Venta Real (Promedio)

precio_promedio = Σ(monto_vendido) / Σ(cantidad_vendida) Datos fuente: byday = { "DD-MM": [unidades, monto] } Ejemplo (producto con múltiples noches): Noche 1: 3 unidades, $30,000 total Noche 2: 2 unidades, $25,000 total Noche 3: 1 unidad, $8,000 total ───────────────────────────── Total: 6 unidades, $63,000 Promedio: $63,000 / 6 = $10,500/unidad

Precio de Lista (Oficial PVP)

precio_lista = valor de "Lista de Precios" en Excel Match en dos pasos (NUNCA fuzzy): 1) Exacto: norm(producto) en PRECIO_LISTA 2) Aplanado: mismo texto, sin espacios/tildes/puntuación 3) Alias: PRECIO_LISTA_ALIAS (confirmadas por dueño) Si no hay match seguro → precio_lista = null (mostrar "—" en tabla) Diferencia visible: Si (precio_lista - precio_promedio) > 5% → resalta en NARANJA Puede indicar: descuento, cambio de precio mid-período, mal cargado en POS

Margen "Sospechoso"

es_sospechoso = margen_% >= SUSP_THR (90%) Acción: • Tablero SUGIERE revisar (auditoría de datos) • Dueño CONFIRMA (estado:"si") o DESCARTA (estado:"no") • Confirmado = NO afecta datos, solo FILTRA tabla/matriz/alertas Causa típica: costo mal mapeado (ingrediente genérico) o precio de trago con valor de botella

Rentabilidad Neta (P&L)

rentabilidad_neta = ingresos - CMV - OPEX Donde: ingresos = Σ(precio_promedio × cantidad) CMV = Σ(costo × cantidad) OPEX = gasto operativo mensual (editado por usuario) Ejemplo (período filtrado): Ingresos: $500,000 CMV: $250,000 (50% del ingreso) OPEX: $100,000 (o prorratedo si filtro) ───────────────── Neto: $150,000 (30% rentabilidad)
Umbral MG_BAJO = 40%
Productos con margen < 40% se clasifican "VACA" (bajo margen). Sirve para:
• Alertas (revisar precios)
• Filtro Rentabilidad (cuadrantes BCG)
• Indicadores de alerta en Resumen

💸 OPEX y Prorrateo

OPEX Total Mensual

OPEX_total = Σ(cantidad × unitario) para todos los rubros confirmados Estructura: [ { cat: "Sueldos", item: "Chef", cantidad: 1, unitario: 150000, confirmado_cero: false }, { cat: "Sueldos", item: "Mozo", cantidad: 1, unitario: 80000, confirmado_cero: false }, { cat: "Servicios", item: "Luz", cantidad: 1, unitario: 15000, confirmado_cero: false }, { cat: "Servicios", item: "Gas", cantidad: 1, unitario: 8000, confirmado_cero: false }, ... ] OPEX_pend = Σ(rubros en $0 no confirmados) Si un rubro tiene cantidad=0 unitario=0, pregunta dueño si es intencional

Prorrateo con Filtros Activos

⚠️ PROBLEMA: OPEX es del bar ENTERO, no de una categoría Si filtras "PIZZAS": Ventas filtradas: $100,000 Ventas totales: $300,000 OPEX completo: $90,000 Si restas OPEX completo → resultado = $100k - CMV - $90k = SIEMPRE negativo Eso no dice nada. SOLUCIÓN: Prorratear OPEX por share de ventas share = ventas_filtradas / ventas_totales OPEX_prorratedo = OPEX_total × share Ejemplo: share = $100k / $300k = 0.333 (33.3%) OPEX_prorrateado = $90k × 0.333 = $30k Entonces: Rentabilidad neta = $100k - CMV - $30k = más significativo IMPLEMENTADO EN: • KPI principal (pie del número) • P&L (nota bajo tabla) • Punto equilibrio (BEQ_prorrateado) • Tarjeta "Peso del OPEX" (si olvidaba × share → 388%)
⚠️ TODO lo que muestre OPEX + ventas filtradas DEBE multiplicar por share
Si agregas widget nuevo: verifica que use share.
Sin filtro: share = 1.0, resultado idéntico a antes.

OPEX con Vigencia por Fecha

opex_periodos = { "2026-01-01": [ { cat, item, cantidad, unitario }, ... ], "2026-04-15": [ { cat, item, cantidad, unitario }, ... ], ... } Motor recorre cada rúbro y asigna el vigente EN LA FECHA del período: • Si período = "01-15 a 02-28" y hay cambio el 01-15 → usa ese • Si período comienza antes del primer cambio → usa el que exista más atrás • Permite cambios de sueldo, servicios, etc. sin borrar histórico Endpoint: POST /api/opex_vigencia

📊 Matriz BCG (Boston Consulting Group)

Clasificación en Cuadrantes

BCG = f(margen_%, volumen_vendido) Cálculo DINÁMICO por rango de fechas elegido (NO estático). Cuadrantes: ┌─────────────────────────────────────┐ │ ALTO VOLUMEN │ │ ┌─────────────┬────────────────┐ │ │ │ ESTRELLA │ VACA │ │ │ │ Alto margen │ Bajo margen │ │ │ │ Alto volumen│ Alto volumen │ │ │ ├─────────────┼────────────────┤ │ │ │ INTERRO. │ PERRO │ │ │ │ Alto margen │ Bajo margen │ │ │ │ Bajo volumen│ Bajo volumen │ │ │ └─────────────┴────────────────┘ │ │ BAJO VOLUMEN │ └─────────────────────────────────────┘ Umbrales: • Margen: MG_BAJO = 40% • Volumen: MEDIANA de unidades del período

Algoritmo de Clasificación

Para cada producto p en período: 1. Calcular margen: (1 - costo/precio) × 100 2. Sumar unidades vendidas Calcular medianas globales (período): mediana_margen = mediana(todos los márgenes del período) mediana_volumen = mediana(todas las cantidades) Clasificar p: if margen >= MG_BAJO and volumen >= mediana_volumen → ESTRELLA if margen < MG_BAJO and volumen >= mediana_volumen → VACA if margen >= MG_BAJO and volumen < mediana_volumen → INTERROGANTE if margen < MG_BAJO and volumen < mediana_volumen → PERRO Excluir: • N/D (sin costo confiable) • Sospechosos confirmados (si filtro "Sin sospechosos" activo)

Scatter Plot

El gráfico muestra cada producto como un punto:

  • Eje X: Volumen (unidades vendidas, log scale a veces)
  • Eje Y: Margen (%)
  • Color: Cuadrante (ESTRELLA=verde, VACA=amarillo, INTERRO=naranja, PERRO=rojo)
  • Tamaño del punto: Ingresos totales del producto (área ∝ ingresos)
✓ Frontend-Only Calculation
BCG se calcula en el navegador (JavaScript), NO en backend.
Permite cambiar rango de fechas sin regenerar datos.
Cuadrantes se re-computan dinámicamente.
⚠️ curItems() vs curItemsBase()
Los cuadrantes usan curItemsBase() (sin filtro de clase) para mantener estabilidad.
Si usaran curItems(), al seleccionar "Perros" los otros desaparecerían y puntos saltarían.

📦 Alertas de Quiebre de Stock

Filosofía: Conteo Puntual, No Inventario Perpetuo

✓ Decisión de Diseño Explícita
Inventario perpetuo (restar cada venta, sumar cada compra) falla si omites una compra.
Mejor: dueño cuenta, sistema resta consumo REAL (ya exacto).

Fórmula de Proyección

Entrada: stock.json = { "Insumo": { cant: N, fecha: "YYYY-MM-DD", umbral_dias: 3 } } restante_hoy = stock.cant × insumo.cant_base - consumo_desde_fecha Donde: • stock.cant está en UNIDADES DE PRESENTACIÓN (ej: 7 botellas) • insumo.cant_base convierte a unidad base (ej: 7 × 330ml = 2,310ml) • consumo_desde_fecha = Σ(consumo_dia[cada noche desde fecha]) Ejemplo: Cerveza Corona Porrón (330ml) Stock anotado: 7 botellas, hace 3 noches cant_base: 330ml/botella Consumo últimas 3 noches: 18 botellas = 5,940ml Restante: (7 × 330) - 5,940 = 2,310 - 5,940 = -3,630ml (FALTA) O si fue la semana pasada: 8 botellas restantes = 2,640ml

Ritmo de Consumo (Estacionalidad)

ritmosRecientes() pondera POR TIPO DE NOCHE (findes vs semana): Ventana: 21 días (3 semanas) para captar cambios recientes (moda, abandono) Para FINDES (Vie, Sáb, Dom real): ritmo_findes = consumo_reciente_findes / noches_de_findes_en_ventana Si no hay muestra de findes en ventana → fallback a promedio histórico Para SEMANA (Lun-Jue): ritmo_semana = consumo_reciente_semana / noches_de_semana_en_ventana Si no hay muestra → fallback a promedio histórico Resultado: dos ritmos distintos, más preciso que "promedio anual"

Proyección Noche por Noche

proyectarQuiebre(insumo, hoy, ritmo_findes, ritmo_semana): restante = stockCalc(insumo, hoy) mañana = hoy + 1 día max_noches = 180 (safety limit) FOR noche = mañana TO mañana+180: IF noche NO abre (patronApertura + dias_cerrados) → SKIP dow = day_of_week(noche - 1 día) // nocheReal() offset IF dow in (Vie, Sáb, Dom): consumo = ritmo_findes ELSE: consumo = ritmo_semana restante -= consumo IF restante <= 0: RETURN noche // fecha de quiebre IF después de 180 noches aún hay stock: RETURN "sin quiebre a la vista" Resultado: "Se agota el jueves 24/07" (más accionable que "X noches")

Umbral de Crítico

STOCK_UMBRAL_DEFAULT = 3 noches Si noches_hasta_quiebre <= umbral_dias → CRÍTICO (rojo) El umbral es AJUSTABLE por insumo (editable en modal).
⚠️ Stock en UNIDADES DE PRESENTACIÓN, no en base
stock.json["cant"] = número de botellas/latas/paquetes
Conversión usa insumo.cant_base (ya validado en los 119 insumos)
Si nuevo insumo sin cant_base → división por 1 (silenciosa, peligro)

Exportar/Importar CSV

Columnas: Insumo; Presentación; Cantidad_actual; Umbral_noches Células vacías → NO TOCAR ese insumo Precio = 0 → rechazar (gratis falsea márgenes) Vista previa OBLIGATORIA: Muestra antes → después Variación % Cuántos productos afecta (hielo en 35 recetas, limas en 22) Resalta cambios > 50% (VARIACION_SOSPECHOSA) Parser: parseNumES() (es-AR, en-US, $, espacios) "8.990,00" (Excel es-AR) → 8990, no 8,99

Filtros Globales (Barra Superior)

Afectan TODO el tablero, incluyendo Resumen:

  • Buscador: Busca por nombre (case-insensitive)

Impacto en Cálculos

curItems = [productos que pasan filtro] KPI = totals(curItems) → Ventas, CMV, OPEX_prorrateado, Margen Ejemplo: "PIZZAS" → filtro activo Antes: Ventas = $500k, OPEX = $100k, Neto = $150k Filtro: Ventas PIZZAS = $100k (20% del total) Nuevos KPI: Ventas: $100k CMV: $35k (solo pizzas) OPEX: $100k × share(0.2) = $20k ← PRORRATEO Neto: $100k - $35k - $20k = $45k Sin prorrateo: $100k - $35k - $100k = NEGATIVO (inutilizable)

curItemsBase = [todos los productos sin filtro de clase/margen] curItems = curItemsBase.filter(mgF y claseF) Dónde se usa: • Tabla Rentabilidad: curItems() • Scatter plot BCG: curItemsBase() ← estable, no salta • Cuadrante labels: curItemsBase() ← permite click de nuevo • Alertas (Resumen): curItemsBase() ← no heredan filtro local • Rentabilidad (Caja): curItemsBase() ← no heredan filtro local Razón: si usaras curItems() en scatter, al seleccionar "Perros" otros desaparecen.

Compras Respeta Filtro por Categoría

DATA.consumo_dia viene del motor YA AGREGADO POR INSUMO. No se sabe qué producto originó cada gramo. Con filtro "PIZZAS": Reconstruir desde productos: consumo = Σ(breakdown[i].qty × unidades_vendidas) Para insumo "Harina": Pizzas margarita: 8 unidades × 250g/unidad = 2,000g Pizzas especial: 5 unidades × 250g/unidad = 1,250g Total harina: 3,250g (solo pizzas) Verificado: reconstrucción = consumo_dia del motor en los 119 insumos Cache: invalidar _cdCache si cambia DATA

Compras: Dos Modos Distintos

modo = "real" | "repo" REAL (historial de consumo): "Con 66 días seleccionados, 477 Stella es lo CONSUMIDO en esos 66 días" No es una lista de compras (sumaría mucho stock) CSV exportado: SIN columna "Comprar" (evita malinterpretación) REPO (qué comprar para reposición): Necesito = consumo próximo ciclo (7 noches × ritmo promedio) Tengo = stockCalc() de insumos vigilados Comprar = max(0, Necesito - Tengo) Columnas: Necesito / Tengo / Comprar CSV: SÍ incluye "Comprar" (es una orden real)

✅ Completitud de Datos

Tarjeta de Completitud

Monitorea: ¿qué días tengo datos de ventas? completitud = días_con_datos / (días_posibles - días_cerrados) Ejemplo: Período: 30 días Dias cerrados (sin apertura): 8 domingos + lunes = marcados por dueño Días posibles abiertos: 30 - 8 = 22 Días con datos: 20 Completitud = 20 / 22 = 90.9% Estado: • 100% ✓ verde • 90-99% ⚠ amarillo ("falta 1 noche") • <90% ✗ rojo ("verificar si hay gap")

Días Cerrados

dias_cerrados.json = { "YYYY-MM-DD": "motivo" } Ejemplo: { "2026-07-05": "Cerrado por reforma", "2026-07-12": "Feriado" } Impacto: • No cuentan como "día sin datos" • Se excluyen de proyecciones de stock (patronApertura) • Visible: "Marcado como cerrado" en modal de día Editable desde: tarjeta Completitud
Desfasaje de Sincronización Conocido (Bistrosoft)
La API de transacciones puede tardar horas en actualizar la noche más reciente.
Si última noche no coincide con Bistrosoft real:
1. Revisar timestamp máximo en API para esa fecha
2. Si es anterior a cierre real → es lag de Bistrosoft, no bug
3. Reintentar más tarde

⚖️ Punto de Equilibrio (Break-Even)

Fórmula Fundamental

BEQ = OPEX / (1 - CMV%) Donde: OPEX = gasto operativo (mensual o prorratedo si filtro) CMV% = costo de mercancía vendida como % del ingreso Ejemplo: OPEX = $100,000/mes Ingresos = $300,000 CMV = $150,000 CMV% = $150,000 / $300,000 = 50% BEQ = $100,000 / (1 - 0.5) = $100,000 / 0.5 = $200,000 Interpretación: "Si vendés $200k con ese costo%, cubrís OPEX y quedás en $0" Actualmente vendés $300k → margen = $300k - $150k - $100k = $50k

BEQ Prorratedo con Filtro

Si filtro "PIZZAS" activo: OPEX_prorrateado = OPEX_total × share CMV% = (CMV_filtrado / ingresos_filtrados) BEQ_prorrateado = OPEX_prorrateado / (1 - CMV%) Nota en tabla: "Calculado con OPEX prorratedo al 20% de ventas totales"

BEQ por Día de Semana

Se calcula para FINS y SEMANA por separado: Fins (Vie, Sáb, Dom real): Ingresos_fins = Σ(ventas noches de find) CMV_fins% = CMV_fins / ingresos_fins OPEX_fins_prorrateado = OPEX × (ingresos_fins / ingresos_totales) BEQ_fins = OPEX_fins_prorrateado / (1 - CMV_fins%) Semana (Lun-Jue): Similar, pero con ingresos de semana Típicamente: BEQ_fins < BEQ_semana (findes vende doble)
✓ Nochereal() Offset
Recuerda: rótulo va +1 día respecto fecha real.
"Sábado" en pantalla = viernes real (cierre domingo madrugada).
Comparar contra Vie/Sáb/Dom real, no contra etiqueta.
